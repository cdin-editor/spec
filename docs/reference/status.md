## Changelog

### Added

- Freeze the Backend-to-Runtime Host API as stable `1.0.0` in a canonical
  normative contract covering descriptor negotiation, required services,
  document operations, snapshots, transactions, notifications, search, UI
  publication, logging, error identities, ownership and owner-thread rules.
- Define Host API compatibility as same-major / minimum-minor; additive 1.x
  minor releases are compatible and breaking changes require a major version.
- Record Runtime package `1.0.0-rc.1` separately from Host API `1.0.0`; retain
  live native integration and extension/migration conformance as stable-package
  release gates.

### Changed

- Accept the Host API freeze under RT-010 and align Backend, Runtime, system
  maps, repository inventory and glossary version labels.
- Specify stable Kernel-status identity and typed Lua error details in the
  Host API contract; retain RT-011 implementation conformance as a verification
  gate until the production adapter vectors pass.

### Not implied

- Runtime package `1.0.0-rc.1` is not a stable `1.0.0` release. The production
  Lua C bridge, native lifecycle/error mapping, RT-013 directory loading and
  RT-020/RT-021 migration parity still require evidence or explicit scope
  decisions.
- No whole-product, Frontend transport or cross-platform production claim is
  made by freezing the Host API contract.
